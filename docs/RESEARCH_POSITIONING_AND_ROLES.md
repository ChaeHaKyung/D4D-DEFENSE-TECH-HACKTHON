# 선행연구 비교·프로젝트 의의·향후 개발·역할분담

## 1. 선행 기술과 우리 시스템의 위치

| 비교 대상 | 기존 기술의 중심 | 우리 시스템과의 차이 |
|---|---|---|
| 전통 CFAR | 주변 해수보다 밝은 표적 탐지 | 육지 마스크, 항만·해안·외해 임계값, AIS 시간정렬, 반복 고정물, 위험점수를 결합 |
| Song et al. 2020 | AIS를 칼만 보간·도플러 보정해 CNN 학습 바운딩박스를 자동 생성 | 우리는 아직 선형보간·CFAR지만, 공개 API 수집부터 웹·로그·검증까지 실행 가능한 OSINT 시스템을 구현 |
| CNN/YOLO SAR 연구 | 정해진 데이터셋에서 탐지 성능 향상 | 우리는 모델 하나보다 데이터 수집·시간동기화·공간매칭·설명 가능한 판정을 먼저 구축 |
| Global Fishing Watch | 전 세계 산업선박을 딥러닝으로 검출하고 AIS matched/unmatched 제공 | GFW는 성숙하고 광역이지만 지연과 범용 정책이 존재; 우리는 부산 해역을 직접 갱신하고 임계값·위험근거를 조정 가능 |
| 단순 AIS 지도 | 송신 중인 선박만 표시 | AIS가 꺼졌거나 위장됐을 가능성을 SAR 비협조 센서로 보완 |

## 2. 차별점

현재의 차별점은 새로운 CNN 구조가 아니라 다음 시스템 설계다.

1. **시간 일치**: 단순 레이어 중첩이 아니라 AIS를 SAR 촬영시각으로 보간한다.
2. **신뢰도 표시**: ±5분 high/medium, ±30분 low를 분리한다.
3. **해안 문맥 반영**: 육지, 해안 1km, 항만, 외해를 구분해 CFAR 임계값을 다르게 쓴다.
4. **다중 날짜 준비**: 같은 위치에 반복되는 후보를 고정시설로 낮추는 장면 이력 구조가 있다.
5. **설명 가능한 결과**: 매칭 거리, 해안거리, AIS 신뢰도, 반복횟수, 위험점수를 함께 보여준다.
6. **운영 재현성**: STAC 검색부터 검증까지 한 명령으로 실행되고 모든 단계가 로그로 남는다.
7. **불확실성 공개**: 미매칭을 불법선박 확정으로 표현하지 않고 검토 후보로 유지한다.

## 3. 프로젝트 의의

- 군·정부 전용 감시자산이 없어도 공개 SAR·AIS로 넓은 해역의 검토 우선순위를 줄 수 있다.
- 사람이 전체 위성영상을 계속 보는 대신 설명 가능한 후보 목록을 제공한다.
- 공개 API와 재현 가능한 로그를 사용해 결과 생성 과정을 감사할 수 있다.
- 향후 불법조업, AIS 위장, 비정상 환적, 해양사고 감시에 확장할 수 있다.
- CFAR 기준선과 검증 체계가 있어 향후 YOLO가 실제로 개선됐는지 비교할 수 있다.

## 4. 객관적인 현재 수준

### 잘된 점

- 학부 해커톤 기준: **상위권을 노릴 수 있는 시스템 통합형 MVP**
- 단순 화면 목업이 아니라 실제 CDSE·AIS 데이터가 연결됨
- 시간보간을 1,321개 숨김 점으로 내부 검증함
- 탐지 결과, 제한, 로그가 웹에서 함께 보임
- 코드가 모듈화되어 팀 개발과 후속 AI 연결이 가능함

### 아직 부족한 점

- 연구논문 수준의 검증된 탐지 모델은 아님
- 실제 처리 SAR 장면이 한 장뿐임
- 1024 PNG 기반 CFAR라 작은 선박 정보가 부족함
- 완전한 역사 AIS와 전문가 정답 바운딩박스가 없음
- 칼만 필터·도플러 위치편이·일대일 최적매칭이 없음
- AIS 지지 재현율 대리지표가 0.25로 현재 탐지 성능은 낮음

정확한 표현은 **“실제 공개데이터 기반 end-to-end 연구 프로토타입”**이다.
“Dark Vessel 탐지 AI 완성품”이라고 표현하면 과장이다.

## 5. 앞으로 할 일의 우선순위

### P0 - 대회 시연 안정화

1. 현재 파이프라인을 처음부터 다시 실행해 데모 순서 고정
2. 성공 로그와 실패 시 대체할 저장 결과 준비
3. `미매칭=확정 Dark Vessel 아님` 문구 유지
4. 현재 설정값과 한계를 발표자료에 명시

### P1 - 데이터셋 만들기

1. 카탈로그의 9개 SAR 장면을 날짜별로 다운로드
2. 10~20m 수준의 VV·VH·입사각 GeoTIFF 생성
3. 각 장면 촬영시각의 신뢰 가능한 역사 AIS 확보
4. 후보를 `ship/fixed/wave/ambiguous`로 사람 검수
5. 날짜·장면 단위로 train/validation/test 분리

### P2 - 융합 정확도 개선

1. 선형보간과 칼만 필터의 숨김 점 오차 비교
2. 선박 속력과 시간차에 따라 매칭반경을 동적으로 변경
3. 최근접 한 개가 아니라 Hungarian 방식의 일대일 매칭
4. SAR 이동표적 Doppler 위치편이 보정
5. 공식 항만경계와 해안거리 데이터로 교체
6. 다중 날짜 고정시설 필터를 실제 9개 장면으로 검증

### P3 - YOLO 탐지기

1. 공개 SAR 선박 데이터로 사전학습 모델 준비
2. 우리 부산 장면의 검수 라벨로 미세조정
3. 입력 채널 후보: VV/VH/입사각 또는 VV/VH/VV-VH
4. 작은 표적을 고려해 512~1024 타일과 중첩 사용
5. 날짜 단위 테스트에서 Precision, Recall, F1, mAP 평가
6. `CFAR only / YOLO only / CFAR+YOLO` 제거실험 비교

### P4 - OSINT 위험도 확장

- 선박 등록·소유·기국·어업허가 교차검증
- AIS 공백 시작·종료와 예상 도달영역
- Ship-to-Ship 접근·정지·동행 패턴
- 분석가가 근거를 확인하고 최종 판정하는 검토 큐

## 6. 4인 팀 권장 역할분담

### 1. SAR·지리 데이터 담당

- CDSE STAC/Process API
- 다중 날짜 GeoTIFF
- VV·VH·입사각 전처리
- 육지·항만·해안 마스크
- 산출물: 날짜별 SAR 폴더와 전처리 보고서

### 2. AIS·데이터 융합 담당

- 현재·과거 AIS 수집
- 데이터 정제와 시간보간
- 칼만 필터, 동적 게이트, 일대일 매칭
- 선박 등록정보 연계
- 산출물: 장면별 AIS 스냅숏과 매칭표

### 3. 탐지·AI·평가 담당

- CFAR 개선
- 사람 검수 라벨 형식
- YOLO 미세조정
- 장면 단위 데이터 분할
- Precision/Recall/F1/mAP와 제거실험
- 산출물: 모델, 예측 CSV, 평가표

### 4. 웹·통합·발표 담당

- Streamlit/Folium 대시보드
- 파이프라인 실행 버튼과 로그
- 위험도와 근거 표시
- 데모 시나리오·발표자료·문서화
- 산출물: 실행 가능한 웹, 시연 영상, 발표 대본

## 7. 협업 규칙

- 파일 형식과 컬럼은 먼저 합의하고 임의로 바꾸지 않는다.
- 기준키는 `scene_id`, `sar_time`, `mmsi`, `candidate_id`다.
- 각 담당자는 입력 파일, 출력 파일, 좌표계, 시간대 UTC를 명시한다.
- API 비밀키는 환경변수로만 사용하며 저장소에 올리지 않는다.
- 알고리즘 변경 전후에 동일 장면의 지표를 기록한다.
- 미매칭·위험점수를 사실 판정이나 확률처럼 표현하지 않는다.

## 8. 심사위원에게 강조할 문장

> 기존 연구가 탐지 모델이나 학습 데이터 생성에 집중했다면, 저희는 공개데이터가 실제로
> 수집되어 SAR 촬영시각에 맞춰지고, 해안 문맥을 반영해 탐지된 뒤, 근거와 불확실성이
> 지도와 로그로 전달되는 전 과정을 구현했습니다. 현재 CFAR는 설명 가능한 기준선이며,
> 다중 날짜 자동라벨과 YOLO를 연결해 성능을 정량적으로 개선할 수 있는 구조입니다.
